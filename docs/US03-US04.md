# US-03 e US-04: disponibilità e test

## Stato

Lettura, validazione, salvataggio transazionale e consultazione delle disponibilità
sono attivi. L'interfaccia JavaFX resta sospesa in attesa del CSS condiviso:
FXML, CSS, controller e Application sono conservati nei commenti dei sorgenti.
I launcher stampano un messaggio senza aprire finestre. Le quattro vecchie risorse
grafiche sono escluse dal JAR con esclusioni puntuali nel `pom.xml`.

Il test grafico commentato è conservato in
[interfaccia-sospesa/DisponibilitaSchermateTest.java](interfaccia-sospesa/DisponibilitaSchermateTest.java),
fuori da `src/test/java`: non è una classe di test attualmente eseguibile.

## Test da IntelliJ e Maven

Ricaricare Maven dopo il pull. Ora si possono avviare direttamente una classe,
un singolo metodo o tutto il package `it.disagili.turnogiusto` con il triangolo
verde di IntelliJ. Non occorrono profili Maven o variabili `MYSQL_*`.

Configurazioni condivise in `.run`:

- **Tutti i test (JUnit)**: esegue tutte le classi attive nel runner IntelliJ.
- **US03 - Repository (database test)**: gli 11 test JDBC di US03/US04 via Maven.
- **US03-US04 - Test senza database**: esclude soltanto il tag JUnit `database`.

Comando ordinario:

```powershell
.\mvnw.cmd test
```

Verifica completa prima della pull request:

```powershell
.\mvnw.cmd clean verify
```

Solo repository oppure solo test senza database:

```powershell
.\mvnw.cmd -Dtest=DisponibilitaRepositoryTest test
.\mvnw.cmd -DexcludedGroups=database test
```

Il vecchio profilo `-Pverifica-disponibilita` resta accettato per compatibilità,
ma non è più necessario. I test JDBC non sono saltati automaticamente. Se manca
MySQL, il messaggio indica come avviare il database di prova; la scelta di
escluderli deve essere esplicita con `-DexcludedGroups=database`.

### Perché l'avvio diretto terminava con -1

Il runner JUnit non ereditava le proprietà e le variabili del profilo Maven.
Il controllo in `@BeforeAll` riceveva `abilitato=false` e `database=null` e
interrompeva la classe prima del primo test. È stato riprodotto in IntelliJ
anche avviando un singolo metodo e verificato con un logpoint del debugger.

Ora l'estensione prepara il database senza condizioni dipendenti da Maven.
I test passano un `FornitoreConnessioni` dedicato a repository e service.
I costruttori ordinari continuano a usare `Database.getConnection()` per l'app;
la classe `Database`, il `.env` e le variabili del processo non vengono modificati.

## Database di prova

Schema: `turnogiusto_us03_test`; utente/password: `turnogiusto_test`;
porta predefinita: `33317`; host: `127.0.0.1`. Sono credenziali soltanto di test.
Il nome dello schema e le credenziali non derivano dal `.env` o da `MYSQL_*`.
Ogni connessione verifica il catalogo; la preparazione e la pulizia lo controllano
nuovamente prima di eseguire SQL di cancellazione.

`MySqlDisponibilitaExtension` opera una volta per l'intera suite:

1. Riutilizza il database di test se già disponibile e lo lascia acceso.
2. Altrimenti cerca `mysqld` nel PATH o nella cartella standard Windows
   `Program Files/MySQL`. È possibile indicarlo con
   `-Ddisponibilita.test.mysqld="C:\percorso\bin\mysqld.exe"`.
3. Inizializza un server separato con `--no-defaults`, bind solo locale e dati
   in una cartella nuova sotto `target/mysql-test`. Crea lo schema condiviso
   `db/init/01_schema.sql`, copiato tra le risorse di test da Maven.
4. Spegne il proprio processo al termine, anche quando un test fallisce.
   Log e dati temporanei restano sotto `target` e sono rimossi da `clean`.

Non servono password amministrative o modifiche al servizio MySQL di sviluppo.
Workbench da solo non contiene il server. Non avviare due suite JDBC
contemporaneamente sullo stesso database: i dati di prova vengono ricreati.

Per cambiare porta usare `-Ddisponibilita.test.port=33318`. Per richiedere un
server già avviato usare `-Ddisponibilita.test.autostart=false`.

### Alternativa Docker e verifica su MySQL 8.4

```powershell
docker compose -p turnogiusto-disponibilita-test -f docker-compose.disponibilita-test.yml up -d --wait
.\mvnw.cmd clean verify -Ddisponibilita.test.autostart=false
docker compose -p turnogiusto-disponibilita-test -f docker-compose.disponibilita-test.yml down -v
```

Il Compose di prova è separato da quello di sviluppo e carica solo lo schema,
non il seed del gruppo. Per cambiare porta impostare `DISPONIBILITA_TEST_PORT`
per Compose e la stessa porta con `-Ddisponibilita.test.port` per Maven/JUnit.
Il binary log è disabilitato su questa istanza temporanea per consentire il trigger
usato nel test di rollback senza privilegi amministrativi.
Vedi le [regole MySQL sui programmi memorizzati e il binary log](https://dev.mysql.com/doc/refman/8.4/en/stored-programs-logging.html).

Il workflow `.github/workflows/test.yml` usa questo stesso Compose su MySQL 8.4
e JDK 21, esegue `clean verify` su push e pull request e arresta il container
alla fine. L'esito remoto sarà disponibile dopo il push.

## File attivi e integrazione

| File/pacchetto | Responsabilità |
| --- | --- |
| `model/` | Dipendenti, contratti, disponibilità, fabbisogni ed enum. |
| `repository/DisponibilitaRepository.java` | Lettura ordinata delle fasce. |
| `repository/SalvataggioDisponibilitaRepository.java` | Sostituzione delle fasce in transazione e rollback su errore. |
| `repository/FornitoreConnessioni.java` | Apre connessioni: configurazione dell'app nei costruttori ordinari, database isolato nei test. |
| `repository/AccessoDipendentiDisponibilita.java` | Contratto di integrazione con il repository dipendenti del team. |
| `repository/DipendentiDisponibilitaJdbc.java` | Lettura di dipendenti/contratti e verifica part-time al salvataggio. |
| `service/DisponibilitaService.java` | Coordina caricamento, salvataggio e consultazione. |
| `service/ValidazioneDisponibilita.java` | Controlla ID, orari, appartenenza delle fasce e duplicati. |
| `service/RiepilogoDisponibilita.java` | Riepilogo anche per part-time senza fasce. |
| `support/MySqlDisponibilitaExtension.java` (test) | Preparazione e arresto del server di prova. |

La futura UI userà `DisponibilitaService`: `trovaPartTime()`,
`caricaFinestre(id)`, `salva(id, finestre)` e `consulta()`.
L'elenco vuoto elimina le fasce; sono ammesse finestre oltre mezzanotte e orari
con secondi, ma non frazioni di secondo o duplicati identici.

Per integrare il repository del compagno, passare un adattatore
`AccessoDipendentiDisponibilita` al costruttore del service. Le firme sono:

```java
List<Dipendente> trovaTutti() throws SQLException;
void verificaPartTime(Connection connessione, int dipendenteId, LocalDate data)
        throws SQLException;
```

La seconda operazione rilegge il contratto nella transazione di salvataggio;
non chiude la connessione e non esegue commit. Blocca la riga del dipendente
con `FOR UPDATE`; per coordinare modifiche simultanee ai contratti, US-02 dovrà
usare lo stesso blocco. Contratti validi sovrapposti vengono segnalati come errore.

## Ripristinare la UI con il CSS condiviso

1. Nei controller e nelle due Application rimuovere i due avvisi iniziali e un
   prefisso `//` da ogni riga conservata.
2. Nei launcher sostituire il corpo temporaneo con l'avvio originale commentato.
3. Recuperare i FXML dal commento archivio al posto della radice vuota, collegare
   il CSS condiviso e adattare le classi di stile concordate.
4. Togliere dal `pom.xml` le esclusioni delle viste ripristinate. Il vecchio CSS
   può rimanere commentato ed escluso.
5. Riportare il test grafico dall'archivio al package `ui` in `src/test/java`,
   rimuovere i commenti e passare `this::apriConnessione` ai suoi repository/service.
   Configurare anche i controller con questi service di prova prima delle azioni.
   Solo allora riabilitarlo con `-Ddisponibilita.test.ui=true` e verificare i FXML.
